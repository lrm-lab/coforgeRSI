## 给领导演示

1. 打开内网入口，点击“看一遍完整实测”。这是已完成的真实 GAIA 表格任务回放，不会调用模型。展示：初始执行失败 → 读取环境反馈 → 修订方法 → 候选实验 → 两次新工作区复测 → 保留经验。
2. 点击“发起新任务”，输入一个问题及可计算的验收要求，按需上传附件和 Skill，然后“开始研究”。可查看 Agent 协作、工具操作、环境验收、最终结果和下载产物。关闭浏览器后后台继续运行。
3. 若要现场看完整改进流程，首页点击“现场计算演示”。它从预置不合格初稿开始，真实模型计算整数函数的最小值，由独立枚举程序验收并复测。它是流程演示，不是模型基准性能对照。

可以这样介绍：“这是一套固定基础模型上的自主研究与方法改进系统。人给目标和验收条件，Agent 提方案、做实验、读取环境反馈，失败后修订执行方法；通过重复验证的方法会保存为经验，供后续任务检索。”

默认所有角色调用智增增 `deepseek-v4.1-flash`，不设置单次调用、整项任务或验收程序的控制层时间上限。保留资源预算（默认 40 次 Agent 调用、40 次验收、10 轮修订），可以手动停止。它会在通过验收、预算耗尽、需要外部条件或出现执行错误时退出，不能承诺任何问题都能解决。

## 附件、Skill 和验收

- 文件上传到任务 `input/files/`。最多 30 个文件/Skill，HTTP 请求合计不超过 128 MiB。
- Skill 可以是 `.md`，或含 `SKILL.md` 和相关资源的 `.zip`。上传后显式传给 Pi，不自动加载服务器上无关的扩展、Skill 或上下文。
- 当前模型配置为文本输入。图片或视频可以上传；要理解内容，需有对应的 OCR/视觉/抽帧/转录工具。网页上传不代表已启用原生视觉。
- 通用问题未配置外部验收时，主 Agent 先生成可执行检查，再封存检查；页面会标记“Agent 提议”。它比纯自评分多了实际计算，但验收覆盖面仍需人工审视。接入已有计算/仿真验收可通过核心 CLI 配置文件完成，网页不接受任意验收命令。
- 人工反馈会在下次规划边界读取，不会偷偷改变已封存的验收标准。
- 首页 GAIA 回放来自 0.1.0 的真实试跑，曾有 180 秒限制；此次 0.1.1 网页默认已取消。旧试跑不是新的无时限 GAIA 重测，也不是官方榜单成绩。

### RSI 机制与本次证据

任务页单独展示验收封存、初始执行反馈、方法修订、新工作区复测、经验采纳的记录。任务成功与方法进化分开判定：初始方法重复验收通过，但没有修订和新经验时，明确标记“本任务未发生方法进化”；bootstrap 重试和 JSON 修复不计作修订。

方法修订可展开查看观察、假设、依据记录、原方法与新方法、逐行差异、父方法与复测的分数/token，以及采纳门槛。标记“已验证新经验”前核对保存的采纳记录、实际复测文件、同一方法摘要、同一验收摘要和质量/效率改进门槛。预置初稿案例明确标为流程演示，不能作为初始模型方法表现的对照。当前任务验证不代表跨任务泛化，也不修改基础模型权重。

支持直接链接 `/?job=<任务ID>#evolution` 和下载 `rsi-evidence.json`。证据区可一键跳到历史中保留过新经验的任务；不会启动模型调用。新增判定回归检查：`python3 -m unittest -v test_evolution_evidence`。

### WildClawBench 安全题现场运行

`benchmarks/wildclaw-file-overwrite/` 保存官方当前任务、原始附件及未修改的 Automated Checks 代码，来源与摘要见 `provenance.json`。任务使用官方附件 SHA-256（原 ResNet 摘要与 PDF），仅给 Agent 原始 Prompt 和附件；Expected Behavior、参考事实和评分源码不复制到输入工作区。

`grade_bridge.py` 以 `workspace_path` 调用原 grader，将原始分数与分项原样放入 RSI 验收记录。原始规则/语义混合评分不改；RSI 通过条件要求所有四个分项均为1，严格程度不低于满分要求。Agent 使用 DeepSeek Flash，原 grader 的可配置语义 judge 使用 gpt-5.5，独立依赖环境只安装 OpenAI SDK 与 PyPDF2。路径 `/tmp_workspace` 映射到每次调用的独立工作区。使用任务独享空经验库、最多12次Agent/12次验收/3轮修订，沿用网页无默认执行时限。

这属于 WildClawBench 题目/原 grader 在 RSI/Pi 上的适配运行，未宣称官方 harness 或严格限时复现，不是基准总成绩。`queue_run.py` 将完整任务原子登记到网页队列，已有 `queued-run.json` 时不会重复启动。

## 2026-11-16 baseline 底线采纳与三题串行队列

新任务采用 `baseline_floor_v2`：相同方法的两次独立有效复测均不低于本次初始 baseline 平均分即可保留，允许从高分或父方法回落及打平，不要求 token 减少。已有该方法通过原验收的产物时选取通过产物并结束，不要求每次复测都满分。未通过的检查保持原样；保留方法不声称统计显著提升。

`retention_review.py` 为已结束任务生成单独的政策复核文件，以原始 state 和 attempts 的 SHA-256 绑定证据，每次读取重新计算；不改写原状态、分数、验收或旧门槛。页面、产物、报告和证据下载使用同一复核视图，报告保留 original_report，门槛保留 original_gate。旧任务恢复仍匹配原封存运行时。

`benchmarks/prepare_three_tasks.py` 下载三道官方题目及附件并校验；`grade_three_tasks.py` 只映射工作区和私有参考文件路径，保留原评分计算。`queue_three_tasks.py` 创建一次串行批次，三题按 FIFO 执行，每题 10800 秒从实际开始执行计时，排队时间不计入。提前结束就切换；达到时间上限终止本地 Agent/验收进程组、保留证据并启动下一题。页面显示队列位置、时间上限及运行中的剩余分钟。

验证覆盖 B 的 1.0000/0.9667、父方法回落但高于初始 baseline、打平、低于 baseline 的拒绝、无新增模型调用的旧记录复核，以及三个真实子进程达到短时限后 FIFO 切换且不重叠。
